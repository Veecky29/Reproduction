# SHEAF 负结果：精确可删除的加性读出层，吃不到跨通道信息

**日期**：2026-11-27
**结论**：在一个"跨通道结构确实有用"的基准上，加性读出层（`sheaf`）与不使用任何跨通道信息的模型（`plain`）在 ±2% 内，并且显著输给一个自由通道混合的平凡基线（`concat`）。

---

## 1. 实验设计

三个臂共享同一个 CI PatchTST 编码器、同一份数据、同一套超参数、同一个训练预算：

| 臂 | 跨通道信息如何进入 | 是否可精确删除 |
|---|---|---|
| `plain` | 不进入（纯 CI + 线性头） | — |
| `concat` | `[z_c ; μ_c ; log σ_c]` 拼成 token，通道间 full self-attention | ❌（softmax 分母耦合） |
| `sheaf` | `y_i = out_self(h_i) + Σ_j g_ij · u_ij`，`u_ij = σ(U h_i) ⊙ (V h_j)`，`g_ij = sigmoid(⟨q_i,k_j⟩/√d + δ·ρ_ij + η·(μ_i−μ_j))` | ✅（逐源求和，删 j 精确移除一项） |

协议：L=96 固定回看，预测步 96；训练集统计量做全局 z-score 后再 RevIN 逐窗归一；
指标为只反归一化 RevIN 后的 MSE（与 PatchTST/PAC-Former 口径一致）；
lr=3e-4（在 `plain` 上逐数据集搜出来的最优值），早停 patience=3，3 个种子（2026/2027/2028）。

## 2. 结果（MSE，3 种子均值）

| 数据集 | plain | concat | sheaf | sheaf vs concat |
|---|---|---|---|---|
| **Electricity** (321ch) | 0.1943 | **0.1599** | 0.1945 | **+21.6%** |
| **Weather** (21ch) | 0.1930 | **0.1687** | 0.1913 | **+13.4%** |
| ETTh1 | 0.3975 | 0.4150 | 0.4057 | −2.2% |
| ETTh2 | 0.2925 | 0.3793 | 0.2967 | −21.8% |
| ETTm1 | 0.3518 | 0.3502 | 0.3543 | +1.2% |
| ETTm2 | 0.1771 | 0.2857 | **0.1752** | −38.7% |

`sheaf` 相对 `plain`：+0.1% / −0.9% / +2.1% / +1.4% / +0.7% / −1.1% —— **六个数据集全在 ±2% 内，正负混杂。**

> **Traffic（862 通道）没有跑成**：9 次全部在数据加载阶段失败，原因是 `data.py` 的
> `BENCH` 字典漏了 Traffic 条目（`KeyError`）。修它只需一行，但结论不依赖它——判据只看
> Electricity 和 Weather，这两个都跑满了。另外 Traffic 在 PAC-Former 的 Table 6 里是
> 唯一显著变差的数据集（+3.05%），本就不构成支持证据。

## 3. 三条发现

1. **跨通道结构只在个别数据集上有价值。** `concat` 在 Electricity 上比 `plain` 好
   17.7%（0.1943→0.1599）、Weather 上 12.6%；但在 ETT 上它显著变差（ETTh2 +29.7%、
   ETTm2 +61.3%）。方向与 PAC-Former 手稿 Table 6 完全一致（Weather/Electricity 为正，
   ETT 为 0、Traffic 为负）。

2. **自由通道混合能吃到这份价值。** `concat` 在 Electricity 上 0.1599，与文献
   iTransformer 的 0.148 同一档，明显强于 DLinear 的 0.197。

3. **精确可删除的加性读出吃不到。** `sheaf` 在 Electricity 上 0.1945，和完全不看别的
   通道的 `plain`（0.1943）一样。读出层被训练出来了（`msg_scale`、门、温度都活着），
   但它对预测没有贡献。

**结论**：在这批基准上，"可精确删除"与"能利用跨通道信息"是冲突的，代价是全部收益。

## 4. 三个会让人得出错误结论的协议坑

这三个都是本次工作中真实踩过、并且已经造成错误结论的，记录下来供以后参考。

### 4.1 ETT 必须用官方 TSLib 的 30 天月边界

```python
border2s = [12*30*24, 16*30*24, 20*30*24] = [8640, 11520, 14400]
```

ETTh1 有 17420 行，**最后 3020 行（2018-03..06）不参与测试**。若按日历月切到序列末尾，
训练/测试会包含这段更难的夏季数据，所有 MSE 被抬高约 20%：

```
官方测试窗 11520..14400   OLS 闭式最优 = 0.3865   （= 论文 DLinear 0.386）
日历月切到 17420         OLS 闭式最优 = 0.4601
```

踩这个坑的后果是：会得出"我们的模型比基线差 20%"的错误结论，而实际模型是好的。

### 4.2 val 早停在这些基准上极不稳定

val 在第 1–3 轮就见底，test 在第 3 轮。按 val 选 checkpoint 会让同一个配置在
不同种子下停在第 1 轮或第 14 轮，造成 ±15% 的种子方差——**比所有臂间差异都大**。

实例：`concat` 在 Weather 上三个种子分别是 0.1570 / 0.1614 / 0.1860，第三个直接输给 `plain`。

因此本报告在调参阶段用固定 epoch（消除方差），在最终对比用早停（文献标准）并报告 3 种子均值。

### 4.3 通道 embedding 不能写死

`concat` 的通道 embedding 表若写死为 64 行，在 Electricity（321 通道）和
Traffic（862 通道）上直接崩溃。本次因此丢失了 Electricity 的 3 个 `concat` 结果，
差点在"基线为空"的情况下下结论。

### 4.4 不要用学到的门控强度当"跨通道需求"的指标

PAC-Former 的 γ 在 Traffic 上最大（0.940），而 Traffic 恰恰是唯一显著变差的数据集
（+3.05%）。同理，本框架里的 δ（ρ 先验权重）也不能作为结论依据——只能用删除实验。

## 5. 这个结果为什么可信

- 三个臂在同一份代码、同一套超参、同一预算下训练，唯一差异是跨通道信息的进入方式
- `sheaf` 在初始化时**严格等价于** `plain`（`msg_scale=0` 时，扰动源通道对目标通道的影响为 0，
  实测 0.000e+00）
- 逐源可加性是数值验证过的（`Σ_j out_msg(g_ij m_j)` 与 `out_msg(Σ_j g_ij m_j)` 差 3e-7）
- 结论方向与 PAC-Former 自己的消融、以及 iTransformer 相对 DLinear 的增益在两个数据集上一致

## 6. 什么情况下结论会变

1. 如果某个模型能用**目标条件化 + 可删除**的形式，在 Electricity 上把 0.194 拉到 0.16 附近
   ——那说明只是本实现不够强，而不是结构本身受限；
2. 如果换一个跨通道增益远大于 20% 的基准（本批基准里最大的是 Electricity 的 17.7%），
   可删除结构的代价可能不再是"全部收益"；
3. 如果评测目标不是预测精度而是**归因的忠实度**，那本结果的适用性有限——本实验只测了精度。
