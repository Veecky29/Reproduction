## 3. P0：会被评审直接击中的问题

### 3.1 手稿的消融结果是反的，报告却正面引用了它

手稿 Table 6、Table A1、Table A4（消融部分，共 28 个 setting × 3 seeds）：

| 数据集 | F 相对 B（四 horizon 均值） | F < B 的 horizon 数 | p < 0.05 且 F 更好 |
|---|---|---|---|
| ETTh1 | +1.89% | 0/4 | 0/4 |
| ETTh2 | +1.21% | 0/4 | 0/4 |
| ETTm1 | −0.05% | 2/4 | 0/4 |
| ETTm2 | +0.42% | 1/4 | 0/4 |
| Weather | **−5.74%** | 4/4 | 4/4 |
| Electricity | **−4.22%** | 4/4 | 2/4 |
| Traffic | **+3.05%** | 0/4 | 0/4（B 更好 1/4，p<0.05） |

也就是说：SCA+PLM 只在 Weather 和 Electricity 上稳定为正，在 Traffic 上显著为负，在 ETT 上基本为零或略负。

报告 1.2 节只写了"γ 在 ETT 上接近 0、在高维数据上打开"这一半，读起来像"PAC-Former 已验证跨变量信息在高维数据上有效"。这会把评审引到一个非常尴尬的对照上：**PAC-Former 唯一显著有效的两个数据集（Weather、Electricity）不是 γ 最大的；γ 最大（0.940）的 Traffic 恰恰是显著变差（+3.05%，H336 的 B 优于 F 还达到 p<0.05）的那个；而 γ 接近 0 的 ETT 则好坏参半。** 三种情况拼在一起，恰好说明 γ 与"跨变量是否有用"没有单调关系。报告没有处理这个反例。

**建议**：不要回避，把它变成动机。正确的叙事是：

> "PAC-Former 的消融显示，跨变量信息在 Weather/Electricity 上有效，在 Traffic 上无效，而 Traffic 的 γ 恰恰最大。这说明 (i) 学习到的门控强度不能作为'跨变量是否有用'的读数；(ii) 用不透明的软注意力做跨变量混合时，我们无法从模型内部判断'哪些边在贡献、贡献给哪个预测步'。这正是需要结构上可分解的读出层的理由。"

这条叙事比现在的"γ 是数据集级 CD 需求指标"强得多，而且它是手稿数据**已经支持**的，不需要新实验。

### 3.2 γ 不能直接当作"数据集级 CD 需求"指标

手稿 6.1 与 Figure 7 的解释是"γ 跟随**数据维度**"（7 → 21 → 321 → 862），不是"CD 需求"。报告把"维度"偷换成了"CD 需求"，并把它写成预期贡献第 3 条。

反例在手稿数据内部就有：ETTm1 与 ETTm2 都是 7 通道，但 γ = 0.160 vs 0.065，差 2.5 倍；如果 γ 度量的是数据集的跨变量耦合强度，同一域、同通道数的两个数据集不该差这么多。更可能的解释是：γ 是**零初始化门控在训练早期被梯度激活的程度**，它受数据集规模、窗口统计异质性、以及"统计先验是否有增量信号"共同影响。

**建议**：把"γ = CD 需求"降级为"待检验假设"，并把 5 节的机制审计前置为它的检验手段。具体做法：对 7 个数据集分别计算 MixBench-TS 的 CD gain 与滞后互信息（作者已开源），画 γ vs CD gain 的散点。**相关系数就是这条贡献的全部说服力**——如果 ρ 很低，第 3 条贡献应当删除；如果 ρ 高，它才配叫"模型内生指标"。这个实验几乎零成本（只需 CD gain 那部分，不用训练）。

### 3.3 新颖性主张已被 2026 年的工作覆盖

报告第 7 节第 1 条："第一个把跨变量依赖做成结构上精确可分解的变量 token 预测器"。这句会被审稿人直接拿证据反驳：

- **DAED**（DASFAA 2026, LNCS 16537, doi:10.1007/978-981-92-0369-7_21）：预测 = 变量主效应 + 成对交互效应之和，内置式（非事后）加性分解，还保留了交互项。这几乎就是 FACT-Former 的"可加读出"母题，而报告全篇未提。
- **PatchDecomp**（arXiv:2603.03902，报告引了，但只归到 B1"内在分解"）：因为它 attention 之后的映射全是线性无偏的，预测**精确分解为逐 patch（含外生变量）的贡献**——这就是"结构上精确可分解"，只是分解维度是 patch 而不是 variable。
- **TempShap**（arXiv:2610.33330）：以 (t, i) 单元为 player 的 Shapley，直接给出 temporal-localization 与 **horizon-impact profile**。报告 I1/I2 说的"很少给出'目标 i × 预测步 h × 来源 j'"因此不再成立，至少"没人做 horizon 维度"这一半需要撤回。
- **FACT**（ICLR 2026，Wang, Shi & Li，"Fine-Grained Across-Variable Convolution"）：用 depth-wise 卷积块 + 多膨胀 2D 卷积显式建模"**随时间的粒度变化的变量交互**"，并在 12 个基准上以更低训练/显存开销达到 SOTA。它针对的正是 G3（一张静态图服务所有预测步）的一阶问题——"细粒度随时间变化的变量交互"——只是用卷积而非 attention 实现。报告把"按预测步分解"当作无人做过的新意，需要至少说明 FACT 的"细粒度"与"按预测步"差在哪里。
- **TiWeaver**（KDD 2026, arXiv:2606.03121）与 **xCPD**（ICLR 2026, arXiv:2603.13702）：TiWeaver 的 FADE 模块专门建模"细粒度**异步**通道依赖"（针对缺失值/非均匀采样），xCPD 做输入感知的通道-patch 路由 + 图谱分解。两者都说明"跨变量依赖不是一张静态图"这个问题已经被从多个角度攻过；报告 G3/G4 的"无人做到按预测步/按状态"需要重新界定边界。
- **IB-Forecast**（arXiv:2607.28124，Information Bottleneck Learning for Faithful Time Series Forecasting Explanations）：这是最要命的一篇。它做的就是"**内在可解释的 MTSF + 忠实度保证 + 稀疏预算控制**"：把预测分解为周期项 + 基于可解释输入 token mask 的残差项，用预算约束的信息瓶颈端到端优化，并配了一套严格的忠实度评测协议；结论是"现有可解释预测器的原生解释忠实度很差，而它在匹配稀疏度下全面超过梯度/遮挡/优化类基线，且只需 14–20% 的观测就能保持低误差"。这直接冲掉报告 I2/I3 的"缺少忠实的跨变量解释"与"事后归因缺少针对预测任务的忠实度基准"两个说法，也正面撞上 FACT-Former 的"忠实度由结构保证"。如果不知道这篇，FACT-Former 的定位会在审稿第一轮就被问住。

**建议**：把新颖性收窄到能被守住的四点，并显式写"相对 DAED/PatchDecomp/TempShap/IB-Forecast 的差异"：

1. 分解维度是 **(source variable × target variable × prediction block)** 的联合，而不是变量主效应（DAED）、patch（PatchDecomp）或单元（TempShap）；
2. 读出层**无 softmax 竞争**，删一条边不影响其他边 → 精确删除一致性（这是 DAED 的交互项与 PatchDecomp 的线性分解都不直接提供的）；
3. 以 CI 预测为锚，因此"自身项 vs 跨变量项"的份额本身可比较；
4. 边来自**统计先验 + 可学习门控**（承接 PAC-Former 的 SCA），因此解释同时带"物理先验"来源。

另外，名字建议换掉：ICLR 2026 已有 FACT，`FACT-Former` 搜索会撞车；"PAC-Former"本身在手稿里也已经是 Pre-filtered, Affinity-Conditioned（报告 1.2 写作 "PAC-Former (ours)" 是对的，但 1.1 表里又并列为已有方法，读者会以为它是已发表工作）。

### 3.4 CI 锚与 PAC-Former 结构不兼容

报告 3.1 说"编码器保持通道独立（PLM 加逐变量编码）"、"跨变量信息只能通过加性读出层加入"。但手稿的 PAC-Former **不是** CI 编码器：变量 token 一旦进入 attention 层，`h_i` 已经是所有变量 token 的凸组合（经过两层 SCA attention + FFN + 残差）。所以：

- 如果 FACT-Former 复用 PAC-Former 的编码器，那 `h_i` 里已经混入了其他变量，"源 j → 目标 i"的加性分解只是**记号上的**，不是信息流上的；
- 如果要严格满足 P1–P3，必须把编码器里的跨变量 attention 全部去掉 → 那就是**另一个模型**（CI 时序编码器 + 加性跨变量读出），不是"在 PAC-Former 之上加一层"。

报告 8 节承认了"加性读出层限制跨变量交互只发生在最后一层"，但没承认更根本的一点：**忠实性与 PAC-Former 的 SCA 是互斥的**。

**建议**：两个方案二选一，并在报告中明确：
- 方案 A（诚实版）：把 FACT-Former 定位为"CI 编码器 + 可分解跨变量读出"，与 PAC-Former 是**替代关系**而非叠加关系；把 PAC-Former 当作"上界参照"（它的精度代表不忠实但有效的跨变量混合能做到什么），FACT-Former 要在**牺牲多少精度**的前提下换来可分解性——这本身就是一个很好的论文卖点（"faithfulness–accuracy trade-off"曲线）。
- 方案 B（保守版）：保留 PAC-Former 编码器，但把解释对象从"源变量对预测的贡献"改成"读出层对最终预测的贡献"，同时明确"编码器内部仍是不可分解的混合"，并把 5 节的机制审计作为对编码器那部分的补充解释。这样 P1–P3 仍然成立，但语义要相应弱化。

### 3.5 "自身预测（CI 锚）"不是 CI 预测

报告 3.2 公式 2 写 `ŷ_i^self = W_s h_i`，其中 `h_i` 是编码器输出。这个量在 PAC-Former 里是**跨变量混合后**的表示，称它为"CI 锚"名不副实。而 CI 锚项 `λ_self · MSE(ŷ^self, y)` 的本意是"让跨变量项表示相对自身预测的增益"——如果锚本身已经含跨变量信息，这个正则的语义就失效了。

**建议**：CI 锚必须是**真正不看其他变量**的预测，两种实现：(a) 用 PLM 之后的 `x̃_i` 直接线性映射（不经过 attention）；(b) 单独训练/冻结一个 CI 预测器（PatchTST 或 DLinear）作为锚。只有这样才能说"自身项 + Σ 贡献"里的"自身项"是可解释的。

### 3.6 P2 与 8 节的"目标侧门控"建议互相矛盾

3.2 的式 6 是 `c_{i←j}^b = a_{ij}^b P_b[V h_j ⊙ σ(U h_i)]`。这里 `σ(U h_i)` 乘在消息**内部**，只要它不依赖 `j`，对固定 `i` 就是一个常数缩放，**加性仍然成立**，P2 没问题。

但 8 节缓解方案写的是"在消息函数中保留目标侧门控 σ(U h_i)"——如果实现时让它依赖 `j`（例如 `σ(U[h_i; h_j])` 或对聚合后的消息做门控），P2 立刻失效。报告需要一句话把这条边界钉死：**消息函数必须对 `j` 线性；任何 `j`-依赖的门控都会破坏精确删除一致性。** 建议直接给出实现约束，而不是留一个"可以保留"的模糊表述。

## 4. P1：方法层面的具体缺陷

1. **`P1–P4` 是定义，不是发现。** P1 是恒等式，P2 是算术，P3 是按块切分。它们作为"性质"写在方法节没问题，但第 7 节把它们当"预期贡献"就弱了。真正需要实验证明的是：(a) 解释是否**稳定**（跨种子/跨窗口的 top-k Jaccard）；(b) 解释是否**恢复真值**（合成数据）；(c) CD 份额是否**与外部度量一致**（P4，也就是 3.2 节那个散点图）。建议把 P4 从"性质"提升为"核心可检验命题"，其余三条降为"由构造保证的实现约束"。

2. **Hard-Concrete 门与"精确"的字面冲突。** 训练时 `a = z · σ(s)` 是连续的，P2 在连续门上精确成立；但 Hard-Concrete 在推理时通常取 `z ∈ {0,1}`（或期望值），此时"屏蔽边 (i,j)"要定义成"把该边的 `z` 置 0"还是"把 `σ(s)` 置 0"，两种定义的删除效应不同。报告应明确 P2 的数值核验是在**连续门**下做的，并说明推理时用的是哪种门。否则"理论为 0"这句话会被抓。

3. **RPG 的 O(N²) 与 G6 自相矛盾。** 报告说 RPG 回应 G6（大 N 效率），但 `A(x) = Σ_k π_k A_k + ΔA(x)` 要显式构造 N×N 矩阵；N=862 时是 74 万个元素/窗口，和稠密 attention 同阶。低秩只是**参数**少，不等于**计算**少。要么老实写"RPG 解决的是参数与状态可解释性，不是计算复杂度"，要么给出低秩不显式展开的实现（`A_k = U_k V_k^T` 时消息可以走 `U_k (V_k^T h)`，复杂度 O(N·r)）——后者其实很自然，报告没写出来，可惜了。

4. **RPG 的原型不可识别。** K 个低秩原型图在潜在基下定义，训练后可能被置换/旋转/混合，与"电网分区、路网拓扑"对照时需要对齐步骤。报告直接说"可与领域知识对照"，缺一句"先按 Hungarian 匹配或按拓扑相似度对齐"。另外 K=8 个状态 + 小 MLP 在 ETT 这种 7 通道、8000 步的数据上容易过拟合，建议在小数据上固定 K=3 或加狄利克雷先验。

5. **RPG 与 xCPD 的定位重叠。** xCPD 已经在做"输入感知的通道-块路由 + 频带专家"，RPG 做"状态原型 + 统计驱动混合"。两者都要回答"何时该开跨变量交互"，报告没有一句话区分。至少要说清：xCPD 路由的是**频带/块**，RPG 路由的是**全局依赖状态**，且 RPG 输出的是可检查的图而不是路由权重。

6. **`λ_0` 的取值与 L0 项的设计不自洽。** 报告建议"目标约 3–10 条边"，又说"λ_0 由验证集上的精度-边数曲线选取"。如果 λ_0 是按验证集精度选的，边数就是结果而不是目标；如果边数是目标，λ_0 就应该按边数约束选。两者只能选一个作为超参，另一个作为报告量。建议明确：λ_0 由验证集**精度**选，边数作为**结果**报告（并给出精度-边数曲线）。

7. **`G_{ij}`（尺度相似度）与 `ρ_{ij}`（滞后互相关）的尺度不匹配。** 式 4 把两者直接相加（`G_{ij} + ρ_{ij}`），但一个是余弦/Gram 相似度、一个是有界的互相关峰值，量纲与取值范围都不同；再乘 `γ` 与 `δ` 两个可学习系数倒是能吸收，但初值怎么设、会不会其中一个主导，报告没说。建议给出归一化方式（例如两者都映射到 [-1,1] 或都做 z-score）与初值。

## 5. P1：实验方案的缺口

1. **缺"统计先验无关"的容量匹配对照。** 这是最关键的一个。现在的对照是"去掉 G、去掉 ρ"（等于去掉先验），但没有"保留同参数量的可学习全局偏置/随机描述子"的对照。审稿人会问：收益到底来自**统计先验**，还是来自**多了一个可学习的跨变量偏置 + 额外容量**？建议加一组 `G_{ij}` 替换为可学习 embedding（同参数量、同初始化），这一组必须显著差于 full model，否则"统计先验有用"这个卖点不成立。

2. **"忠实度由结构保证"这个卖点已被 IB-Forecast 占位。** IB-Forecast（arXiv:2607.28124）已经用"内在可解释的 token mask 分解 + 信息瓶颈稀疏预算 + 严格忠实度协议"把"可解释 + 可验证 + 稀疏可控"三件事一起做了，并且明确报告了"现有 intrinsic 解释器忠实度差"。FACT-Former 如果还以"第一个让解释忠实度由结构保证"立论，会被直接对标。可行的差异化只剩两点：(a) IB-Forecast 的分解单元是 input token（时间 × 变量），FACT-Former 是 (source variable × target × prediction block)，后者能回答"哪个变量对哪个目标的哪个预测步贡献多少"，前者不能；(b) IB-Forecast 用 mask + 信息瓶颈控稀疏，FACT-Former 用 Hard-Concrete + L0 且带统计先验。报告必须把这两点写清楚，否则第 7 节第 1 条无法成立。

3. **基线调参协议与 G1 的诉求冲突。** 6.2 写"按开源代码与原文设置"，但 MixBench-TS 的核心主张就是"必须在统一协议下重调基线，否则 CI/CD 的比较是错的"。如果 FACT-Former 用调过的超参、基线用原文超参，在 MixBench 上赢了也会被说成 cherry-picking。建议：**所有基线在 MixBench 的 10 个数据集上按 MixBench 的统一协议重调**（他们已开源调参代码），并在报告里明确写出这一条。这会让算力估计上升，见下条。

4. **算力估计偏乐观。** 报告写 MixBench-TS"本方法 + 6 基线，约 280 次，25–30 GPU·h"，等于每次约 6 分钟。但手稿自己的 Traffic 单次是 30–45 分钟，MixBench 里的 PeMS 系列（170–883 通道）不会更便宜。按 10 数据集 × 7 方法 × 4 horizon × 3 seeds ≈ 840 次、平均 15 分钟算，仅 MixBench 就要 200+ GPU·h；再加上"基线按统一协议重调"的搜索成本（每个 setting 12 配置 × 7 基线），总算力会到 400–600 GPU·h，即单卡 3–4 周，不是 4–5 天。建议重算，并在报告里区分"主方法训练"与"基线调参"两块。

5. **3 个种子不够支撑"解释稳定性"的结论。** 稳定性指标（跨种子 Jaccard、跨窗口 Jaccard）在 n=3 下方差极大，容易得出"稳定/不稳定"的偶然结论。建议解释相关实验用 5–10 个种子（只跑解释，不重训，成本低）。

6. **缺"解释是否真的被使用"的验证闭环。** 报告有删除曲线、有真值恢复，但缺一个关键实验：**用解释去干预模型**（例如只保留 top-k 边、或按解释排序逐步加边），看精度是否按解释预测的方式变化。Choi et al. 的 bounded post-hoc support 就是这类"解释 → 干预 → 验证"的范式，报告引了它却没借用它的实验设计。

7. **"三层验证"的第一层过重、第三层过轻。** 合成数据（VAR/Lorenz-96/Kuramoto/状态切换 VAR）能提供真值，但它与真实数据的耦合形态差距大；而真实的强耦合数据（MixBench 的 10 个、PeMS、ODE 基准）报告只当成"证明 CD 价值"的靶子，没当成"真值恢复"的靶子。建议把第三层拆成"真实强耦合数据上的**部分真值**"（例如 PeMS 的路网拓扑、MixBench 的 planted coupling 报告），这样"真值恢复"就不只依赖合成数据。

## 8. P2：战略与节奏

1. **先导研究应前置。** 现在的节奏是"1–2 周合成数据与机制审计 → 3–5 周主方法"。但机制审计的结论（γ 到底度量什么、SCA 到底用了哪些变量）会直接决定 FACT-Former 的设计（CI 锚怎么定义、编码器要不要去 attention）。建议改成"第 1 周只做机制审计 → 第 2 周据此冻结方法设计 → 第 3 周起跑主实验"。这样能避免"跑到第 6 周发现锚的定义要改，全部重跑"。
2. **投稿窗口的判断可以更细。** 报告写"KDD、ICML、NeurIPS 2027 轮次（以官网截止日期为准）"。以 2026-11 为起点，8 周计划对应 2027-01 中旬，正好卡 ICML 2027（通常 1 月下旬）与 KDD 2027（通常 2 月上旬）的窗口；NeurIPS 2027（5 月）则太晚。建议明确写"目标 ICML 2027 / KDD 2027，NeurIPS 2027 作为 fallback"，并倒推每个实验的 deadline。
3. **前导审计单独成文的策略要谨慎。** 报告说"可以单独成文"。但审计结论（"γ 与真实使用量不单调"）正是 FACT-Former 的核心动机；先发审计，等于把主方法的 motivation 提前公开。建议：要么审计只作为 arXiv 预印本 + 主方法的技术报告一起发，要么审计投 TMLR（审稿周期长），主方法投会议，时间上错开。
4. **PAC-Former 手稿的定位要写清楚。** 报告通篇把 PAC-Former 当作"已确立的工作"，但手稿明显还在投稿阶段（有 CRediT、竞争声明、data availability、GitHub 链接）。如果 PAC-Former 尚未接收，FACT-Former 的"在 PAC-Former 之上"就有自我引用风险（双盲）。建议报告开头加一句状态说明（"PAC-Former 目前处于投稿/修订阶段"），并在 FACT-Former 的写作中把 PAC-Former 当作 concurrent work 处理。
5. **"不使用任何 LLM/基础模型"是优点还是局限？** 报告把它写成算力上的优点。但在 2026 年的 TSF 评审里，"不做 foundation model 对照"本身会被问（Chronos/TimesFM/Moirai 这类模型在零样本上的表现已经是标配对照）。建议至少加一组"与一个开源 TSFM 的零样本/轻微微调对比"，或者在 limitation 里明确说明"本文聚焦从零训练的小模型，TSFM 对照留待后续"。这不会增加多少算力（推理即可）。

## 10. 一句话总结
