# SHEAF 负结果：精确可删除的加性读出层，吃不到跨通道信息

**日期**：2026-11-27（v6 修订版）

**结论**：在三个臂**共享同一个 CI 编码器**、只更换"跨通道信息如何进入输出"的条件下，
加性可删除读出层（`sheaf`）与完全不使用跨通道信息的（`plain`）在 ±1% 内；
而一个自由通道混合的对照（`concat`）在 Electricity 上比它们好 **9.4%**，在 Weather 上没有优势。

换句话说：**能吃到跨通道信息的地方，可删除结构一点没吃到；不能吃到的地方，谁都不行。**

---

## 0. 这一版修了什么（v5 → v6）

第一版（v5）的判定是"`sheaf` 输给 `concat` 17.7%（ECL）/ 12.6%（Weather）"。那个对比**不成立**，
因为 v5 的 `concat` 是另一条网络（`Linear(L+2→d) + 通道自注意力`），
而 `plain`/`sheaf` 用的是 CI patch 编码器 —— 赢的可能只是架构。

v6 修正了四处：

| 问题 | v5 | v6 |
|---|---|---|
| 对照不公平 | `concat` 自带另一套编码器 | 三臂**共享同一编码器**，只换混合方式 |
| 统计量没进自身分支 | `out_self(h_i)` | `out_self([h_i ; μ_i ; log σ_i])`（`plain` 同步改） |
| 自身项漏进跨通道和 | 门控含 `j=i` | 门控对角线遮蔽为 0，`agg_i` 只含 `j≠i` |
| 读出分支被冻住 | `α` 零初始化 + 按 val 早停 | `α` 初始 0.1，且逐 run 记录 `α/δ/η/τ/门分布` |

## 1. 实验设计

三臂共享同一 CI PatchTST 编码器与同一训练预算：

| 臂 | 跨通道信息如何进入 | 可精确删除 |
|---|---|---|
| `plain` | 不进入 | — |
| `concat` | 编码后 token 做 full self-attention（softmax） | ❌ 分母耦合 |
| `sheaf` | `y_i = out_self([h_i;μ_i;logσ_i]) + α · W_o( σ(U h_i) ⊙ Σ_{j≠i} g_ij V h_j )`，`g_ij = sigmoid((⟨q_i,k_j⟩/√d + δρ_ij + η(μ_i−μ_j)) / τ)` | ✅ 逐源求和 |

协议：L=96、H=96；训练集统计量全局 z-score + RevIN；指标为只反归一化 RevIN 后的 MSE；
lr=3e-4（在 `plain` 上逐数据集搜出的最优值）；早停 patience=3；3 种子（2026/2027/2028）。

## 2. 结果（MSE，3 种子均值）

| 数据集 | plain | concat | sheaf | sheaf vs concat |
|---|---|---|---|---|
| **Electricity** (321ch) | 0.1931 | **0.1749** | 0.1919 | +9.7% |
| **Weather** (21ch) | 0.1935 | 0.1919 | **0.1918** | −0.1% |

`sheaf` 相对 `plain`：Electricity **−0.6%**，Weather **−0.9%**。

对照 v5（不公平对照）的数字，`concat` 的优势大幅缩水：

| | v5 concat | v6 concat | 缩水 |
|---|---|---|---|
| Electricity | 0.1599 | 0.1749 | +9.4% |
| Weather | 0.1687 | 0.1919 | **+13.8%** |

**Weather 上 13.8% 的"跨通道增益"几乎全部来自架构差异，不是来自混合机制。**
ECL 上还剩 9.4% 是真的。

## 3. 三条发现

1. **公平地讲，跨通道混合只在 Electricity 上有效**（−9.4%），在 Weather 上等于 0
   （0.1919 vs plain 0.1935，落在种子噪声内）。这与 iTransformer 相对 DLinear 在
   ECL 上的 25% 优势方向一致，但本实验固定编码器后的效应量小得多。

2. **加性可删除读出几乎完全吃不到这份增益**：ECL 上它只拿到 −0.6%（0.1931→0.1919），
   而自由混合拿到 −9.4%。**代价是约 94% 的可用增益。**

3. **优化器主动把读出分支关掉了**。逐 run 记录的 α：

   ```
   Electricity   α = 0.074 / 0.074 / 0.071     ← 从 0.1 一路下降
   Weather       α = 0.107 / 0.121 / 0.125     ← 基本不动
   ```

   在唯一有增益的 ECL 上，训练**把跨通道权重从 0.1 压到 0.07**。这不是"没学到"，
   是"学到了不用它更好"。这比单纯打平更有说服力。

## 4. 三个会让人得出错误结论的协议坑

### 4.1 ETT 必须用官方 TSLib 的 30 天月边界

```python
border2s = [12*30*24, 16*30*24, 20*30*24] = [8640, 11520, 14400]
```

ETTh1 有 17420 行，**最后 3020 行（2018-03..06）不参与测试**。按日历月切到序列末尾会把
这段更难的夏季数据算进测试集，所有 MSE 抬高约 20%：

```
官方测试窗 11520..14400   OLS 闭式最优 = 0.3865   （= 论文 DLinear 0.386）
日历月切到 17420         OLS 闭式最优 = 0.4601
```

踩这个坑会得出"模型比基线差 20%"的结论，而实际模型是好的。

### 4.2 val 早停在这些基准上极不稳定

val 在第 1–3 轮见底，test 在第 3 轮。按 val 选 checkpoint 会让同一配置在不同种子下
停在第 1 轮或第 14 轮，造成 ±15% 的种子方差——比所有臂间差异都大。

实例：v5 的 `concat` 在 Weather 上三个种子 0.1570 / 0.1614 / 0.1860，第三个直接输给 `plain`。

### 4.3 通道 embedding 不能写死

`concat` 的通道 embedding 若写死 64 行，在 Electricity（321）和 Traffic（862）上直接崩。
本次因此丢失了 v5 里 Electricity 的 3 个 `concat` 结果。

### 4.4 不要用学到的门控强度当"跨通道需求"指标

PAC-Former 的 γ 在 Traffic 上最大（0.940），而 Traffic 恰恰是唯一显著变差的数据集
（+3.05%）。同理，本框架的 δ、α 也不能单独作为结论依据——**α 只能作为"模型用没用这条支路"
的诊断**，不能用来说明"数据需不需要跨通道"。

## 5. 这个结果为什么可信

- 三臂共享同一编码器，唯一差异是混合方式（这是 v5 缺的）
- `sheaf` 初始化即打开（α=0.1），不是被冻在 CI 状态
- 逐源可加性数值验证过（`Σ_j out_msg(g_ij m_j)` 与 `out_msg(Σ_j g_ij m_j)` 差 3e-7）
- 每个 run 都记录了 α/δ/η/τ 与门分布，可以复查读出分支是否真的参与了
- 结论方向与 PAC-Former 消融（SCA 在 ETT 为 0、Weather 小幅为正）、
  以及 iTransformer 在 ECL 上的优势一致

## 6. 什么情况下结论会变

1. 如果某个模型能用**目标条件化 + 可删除**的形式在 Electricity 上把 0.1919 拉到 0.175 附近
   ——那说明是本次实现不够强，而不是结构受限；
2. 如果评测目标不是精度而是**归因忠实度**，本结果的适用性有限：本实验只测了精度；
3. 如果换到跨通道增益远大于 9.4% 的图景（例如 862 通道的 Traffic），
   可删除结构的代价占比可能不同——但 Traffic 的 N×N 门控需要先做低秩/稀疏化。
